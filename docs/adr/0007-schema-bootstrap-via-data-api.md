# ADR 0007: Schema bootstrap through the RDS Data API, then disable it

- Status: accepted
- Date: 2026-10-04

## Context

The table, the index and the two database users must exist before the API works. Aurora is private, there is no NAT,
no VPC endpoint and no bastion, so a SQL client on a workstation or in the pipeline cannot reach it. The functions run
inside the VPC but must not hold the master password.

## Decision

`scripts/init-schema.sh` applies `scripts/sql/schema.sql` once, idempotently, to the **primary** cluster through the
**RDS Data API**, which reaches the cluster from the AWS side. The master credentials come from the Secrets Manager secret
generated by the primary database stack (`MasterSecretArn`, name `sm-useast2-drdemo-master-prod-<suffix>`; RDS cannot manage the master password of a
global database); the Data API reads the secret itself and the script never reads or prints it. `scripts/deploy.sh`
enables the Data API (`EnableDataApi=true`) only for this step, runs the script, and redeploys the primary stack with
`EnableDataApi=false`, then verifies `HttpEndpointEnabled` is `False`. An exit handler tries to close it if the deploy
fails in between. The objects replicate to the secondary.

## Consequences

- While the Data API is on, any principal holding `rds-data` permissions and the master secret could run SQL as master.
  Mitigations: it is on only during the bootstrap, IAM is scoped to the cluster and secret ARNs, and the deploy checks it is off.
- The Data API on the primary cluster of a Global Database works: the schema bootstrap ran at the first deployment (2026-10-14) after
  one fix (the bootstrap retries while the endpoint is being enabled). Fallback if it ever fails: run `scripts/sql/schema.sql` with
  `psql` from an in-VPC session as the master user.
- The step is skipped when the roles are swapped ([ADR 0005](0005-database-stacks-not-redeployed-during-drills.md)).
- After a failover the master secret of `us-east-2` is unreachable ([runbook](../dr-runbook.md)); the application is unaffected.

## Alternatives considered

A bastion, an EC2 instance or a Lambda inside the VPC with the master password (more components and a secret to carry);
a NAT gateway or VPC endpoints for Secrets Manager (fixed monthly cost); running SQL from every function at start-up
(would need DDL rights in the application user).
